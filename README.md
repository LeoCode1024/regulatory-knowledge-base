# 监管制度知识库

当前版本：`1.19.0`

这是一个面向财险监管制度的 Obsidian Markdown 知识库。它不是把制度逐篇做摘要，而是把 `raw/` 中的原始制度、办法、通知、指引和监管规则，整理成可追溯、可执行、可复用的监管知识系统。

知识库的核心目标是：在真实工作问题中快速找到监管结论、办理流程、材料清单、责任主体、时限要求、风险后果，并能一路回溯到具体来源条款和原始资料。

## 适用场景

本库适合用于以下工作：

- 公司治理、董事会、股东会、监事会和高级管理层职责梳理
- 董监高任职资格、履职评价、离任审计和培训管理
- 股权变更、大股东行为、关联交易识别审批披露
- 分支机构设立、变更、退出和许可证管理
- 信息披露、监管报送、监管统计和数据安全
- 合规管理、内部控制、操作风险、声誉风险和突发事件处置
- 消费者权益保护、销售行为、投诉处理和互联网保险
- 资金运用、偿付能力、资本管理、准备金和再保险
- 现场检查、行政处罚、监管评级和整改闭环

## 知识库结构

```text
.
├── raw/                  # 原始资料层，保持原貌，不随意改写
├── wiki/
│   ├── 来源/              # 来源证据页，按制度逐条抽取证据
│   ├── 专题/              # 跨制度专题页，形成实务口径
│   ├── 场景/              # 工作场景页，说明触发、流程、材料和风险
│   ├── 清单/              # 可执行检查表、材料清单、报送清单
│   ├── 概念/              # 概念入口，帮助判断适用边界和检索证据
│   ├── 枢纽/              # 工作地图，按业务域串联知识页
│   ├── 对照/              # 新旧制度或相近制度差异对照
│   └── 证据总索引.md      # 全库证据索引
├── tools/                # 重建、格式化和校验脚本
├── index.md              # 知识库导航入口
├── log.md                # ingest、重构和重要修订记录
├── AGENTS.md             # 知识库维护规则
└── VERSION               # 当前语义化版本号
```

## 各层如何使用

### 1. 从导航或工作地图进入

日常检索建议先打开 `index.md`，再进入 `wiki/枢纽/` 下的工作地图。工作地图按业务域组织，比如公司治理、股权与关联交易、风险内控合规、信息披露与报送、消费者保护与销售管理等。

### 2. 用专题页形成监管口径

`wiki/专题/` 不是单个制度摘要，而是围绕一个长期工作问题，把多个制度中的职责、权限、流程、时限、限制和责任后果归并成可执行的实务口径。

例如：

- 董事会职权与授权边界
- 董事会秘书职责与治理辅助机制
- 股权事务与大股东行为管理
- 关联交易识别审批披露
- 重大事项和信息披露
- 首席合规官和合规管理职责

专题页中的每个职责点或监管要求点后面都保留来源条款链接，便于回查。

### 3. 用场景页办理具体事项

`wiki/场景/` 面向“发生某件事时应如何处理”。每个场景页通常包括：

- 触发场景
- 适用对象
- 责任分工
- 办理流程
- 审批、会议、报送或披露要求
- 时限控制
- 材料和留痕
- 风险后果
- 来源证据

例如，关联交易事项可以进入 `wiki/场景/关联交易审批披露流程.md`，按识别、审查、回避、董事会审议、披露、报告等步骤处理。

### 4. 用清单页做检查

`wiki/清单/` 将监管要求转化为可核对事项。适合用于内部检查、材料准备、监管报送前复核和整改跟踪。

清单页一般按以下字段组织：

- 检查事项
- 适用情形
- 责任主体
- 依据
- 频率或时限
- 留痕材料
- 完成情况

### 5. 用概念页判断边界

`wiki/概念/` 不是简单标签堆叠。概念页用于帮助判断一个事项是否落入某类监管问题，通常包括：

- 工作定义
- 适用边界
- 高频主体
- 高频动作
- 时限控制
- 责任后果
- 实务判断方法
- 常见误区
- 代表证据

正式结论仍应回到专题页、场景页、清单页和来源条款确认。

### 6. 回到来源页和 raw 原文核对

`wiki/来源/` 是证据页，不是读后感。来源页按实际条款号建立锚点，例如 `### 第二十九条`。专题、场景、清单引用依据时，会链接到来源页的具体条款标题。

正式写材料、出具意见或做制度修订时，应遵循：

```text
专题/场景/清单 → 来源页具体条款 → raw 原始资料
```

## 维护原则

维护本知识库时，应遵循 `AGENTS.md` 中的规则，尤其是：

- `raw/` 保持原貌，不为了排版或跳转改写原始资料。
- 每份进入 `raw/` 的资料，应有对应 `wiki/来源/` 页面。
- 来源页必须包含具体条款证据，不写空泛摘要。
- 专题页必须跨制度整合，不复制单篇制度原文。
- 场景页必须能指导办事，说明触发、责任主体、流程、材料、时限和风险。
- 清单页必须能直接检查。
- 重要判断、职责、时限、限制、处罚和监管措施必须可追溯。
- 不确定事项应标注“待核对”或“需进一步核验”，不能编造。

## 新资料 ingest 流程

新增资料进入 `raw/` 后，推荐按以下顺序处理：

1. 核对 raw 原文，确认制度名称、状态、适用范围和条款结构。
2. 建立或更新 `wiki/来源/` 下的来源证据页。
3. 完整抽取条款和枚举项，避免只抽第一项。
4. 更新受影响的跨制度专题页。
5. 更新或创建相关场景页和清单页。
6. 更新概念页、枢纽、对照页和证据总索引。
7. 更新 `index.md` 和 `log.md`。
8. 运行重建、格式化和校验脚本。
9. 用 Git 提交一个可追踪版本。

## 重建与校验

常用命令：

```powershell
python tools/rebuild_wiki.py
python tools/format_markdown.py --target wiki
python tools/validate_wiki.py
```

校验重点包括：

- raw 文件是否都有对应来源页
- 来源页条款锚点是否真实存在
- 是否存在断链
- 是否存在 `line XXX` 形式的正式依据引用
- 枚举项是否遗漏
- 专题页是否退化为空泛说明文
