# 数据安全事件和监管统计报送流程

## 一、监管结论

数据安全和监管统计应按“分类分级、处理管控、外包和系统控制、统计质量复核、事件报告、整改复盘”闭环办理。实务中要把数据安全事件和统计报送放在同一证据链里管理：数据来源、加工规则、复核记录、报送版本、事件处置和监管反馈都要可回溯。

## 三、办理流程

### 1. 分类分级和数据目录维护

- 数据管理部门维护数据资产目录，标明数据来源、责任部门、分类分级、重要数据标识和使用场景。
- 涉及客户信息、经营数据、监管统计口径或重要数据的，应在系统上线、报送模板调整、外包处理前完成分级复核。
- 重要数据识别和分类分级调整应留存审批、复核和版本记录。

依据：[[wiki/来源/11_信息披露与数据管理/银行保险机构数据安全管理办法#第十一条|《银行保险机构数据安全管理办法》第十一条]]、[[wiki/来源/11_信息披露与数据管理/银行保险机构数据安全管理办法#第十五条|第十五条]]、[[wiki/来源/11_信息披露与数据管理/银行保险机构数据安全管理办法#第二十一条|第二十一条]]。

### 2. 数据处理和外包风险控制

- 数据处理活动应先核对处理目的、数据范围、授权依据、最小必要原则和留痕方式。
- 供应链、信息科技外包或受托方处理数据时，应把数据安全主体责任、转委托限制、共享限制和安全缺陷报告写入合同和验收清单。
- 受托方存在安全缺陷、漏洞隐瞒不报或未整改的，应按合同处罚、取消服务资格，并按要求报告监管。

依据：[[wiki/来源/11_信息披露与数据管理/银行保险机构数据安全管理办法#第三十一条|《银行保险机构数据安全管理办法》第三十一条]]、[[wiki/来源/11_信息披露与数据管理/银行保险机构数据安全管理办法#第三十二条|第三十二条]]、[[wiki/来源/11_信息披露与数据管理/银行保险机构数据安全管理办法#第六十八条|第六十八条]]。

### 3. 监管统计报送和质量校验

- 统计归口部门应在报送前核对数据来源、统计口径、系统抽数逻辑、人工调整事项和复核人员。
- 报送后如发现差错，应区分口径理解、系统取数、人工填报、数据源质量等原因，形成更正说明和整改记录。
- 监管统计资料和底稿应能支持监管查询、现场检查和内部问责。

依据：[[wiki/来源/11_信息披露与数据管理/银行保险监管统计管理办法#第十九条|《银行保险监管统计管理办法》第十九条]]、[[wiki/来源/11_信息披露与数据管理/银行保险监管统计管理办法#第二十一条|第二十一条]]、[[wiki/来源/01_法律与行政法规/中华人民共和国保险法(2015修正)#第八十六条|《中华人民共和国保险法(2015修正)》第八十六条]]。

### 4. 数据安全事件报告和整改

- 发生数据泄露、篡改、毁损、重要系统安全缺陷、外包服务安全事件或监管统计重大差错时，应立即开展影响评估。
- 需要报告监管的，应明确报告对象、时限、口径、责任人和后续补报安排。
- 整改应覆盖技术修复、权限收回、流程修订、供应商问责、数据补正和员工培训。

依据：[[wiki/来源/02_公司治理与机构管理/银行保险机构操作风险管理办法#第四十二条|《银行保险机构操作风险管理办法》第四十二条]]、[[wiki/来源/11_信息披露与数据管理/银行保险机构数据安全管理办法#第六十八条|《银行保险机构数据安全管理办法》第六十八条]]。

## 四、材料和留痕

| 材料类型 | 留痕内容 |
| --- | --- |
| 数据治理 | 数据目录、分类分级清单、重要数据识别、权限矩阵 |
| 处理活动 | 数据处理审批、系统日志、外包合同、转委托审批、脱敏记录 |
| 统计报送 | 报表版本、取数脚本或口径说明、复核记录、报送回执、差错更正 |
| 事件处置 | 事件发现记录、影响评估、监管报告、处置方案、整改复核 |

## 五、风险后果

- 数据安全义务履行不到位，可能引发监管问询、责令整改、外包服务资格取消或行政处罚。
- 监管统计报送不真实、不准确、不完整，可能触发保险法下的资料报送和虚假资料责任。依据：[[wiki/来源/01_法律与行政法规/中华人民共和国保险法(2015修正)#第一百六十九条|《中华人民共和国保险法(2015修正)》第一百六十九条]]、[[wiki/来源/01_法律与行政法规/中华人民共和国保险法(2015修正)#第一百七十条|第一百七十条]]。
